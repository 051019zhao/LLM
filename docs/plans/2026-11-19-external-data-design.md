# 08：从稀缺训练样本转向公开扩展数据

目标是争取 Kaggle Balanced Accuracy 超过 0.41，不能由离线验证保证公榜或私榜分数。

## 选择依据

03/04/06 的真实公榜为 0.368/0.363/0.361；07 的嵌套提示词分组验证仅提高约 0.009，区间包含零。继续微调同一小样本表示缺乏支持。

检索并阅读了 SSanjay0614/Name-That-LLM-Kaggle、stewari1210/name-that-llm、richardharnisch/name-that-llm 的公开方法及 Open Pool 数据卡。三条路线：

1. **优先：公开扩展文本 + 加权多视图 SVM。** CPU 能运行、易复现，直接检验增加数据的效果。
2. 冻结语言模型的 token 统计或风格嵌入。可提供独立信号，但本机 torch 为 CPU 版，数十亿参数模型需要 Kaggle GPU 和额外权重输入。
3. 多个 LoRA/DeBERTa 专家的大融合。公开作者报告高分，资源和依赖很多；不把作者成绩当成本队成绩，也不直接照搬不明许可的代码。

## 预定实验

- 保留 03；08 独立实现，采用字符、词、词形、功能词四种 TF-IDF，词表仅在该折训练文本上拟合。
- 扩展集固定版本；删除不合法标签、空值、重复、冲突标签及来源标识的训练提示词再生成、Gemini 3.7 路由风险。
- Open Pool 的 match_weight/style_score 使用了完整官方训练数据，**不用于本次分组验证**。数据发布者的清洗仍有全训练集排版信息，验证必须披露这项局限。
- 固定线性 SVM C=0.5，官方样本基础权重 12，扩展样本 1；按有效权重平衡类别。按类限量，避免最大来源压倒官方数据。
- 第一步在 dev 提示词比较同一模型有/无扩展数据，另列 03；选择后才读取本轮留出提示词分数。旧实验已使用整个训练集，不能称这份留出是历史上从未使用过的独立测试集。
- 避免假设隐藏测试有每提示词 18 条、各类数量相同，不使用硬配额或全量类别均分配。
- 保存逐折、逐类、长度分层和提示词 bootstrap 区间。公榜仍未知时明确写“未提交”。
